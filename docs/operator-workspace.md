# Scoped Homelab operator workspace (#77 / #83)

SOURCE ONLY. Owner product direction 2026-11-25: optimize usefulness against risk, enable novel scoped work rather than per-question tools. This extends the existing always-on Work Runner; no SSH into the same machine is necessary. Remote Codex WSL keeps its accepted offline boundary. A later SSH transport may target a separately constrained account, never an administrative key or unrestricted remote shell.

## Capabilities and limits
Same private control transport and work.submit/status/cancel, same ledger and one-attempt lifecycle. New optional task type workspace.operator-python.v1, same generic fields plus scope_id and access (read/write). The operator chooses scope policy in a root-owned local file. No caller paths, hostnames or credentials. Python has ordinary read/write access to explicitly granted directory trees, including SQLite copies, datasets, configs prepared for review, and reusable scripts. The rest of the host, Docker socket, SSH keys and network remain inaccessible by design. The existing offline profiles stay unchanged. No live grant is created by source merge.

A write grant permits arbitrary modification/deletion within the dedicated scope. Do not mount entire /data, home, production databases, live executable/config trees, service sockets, credentials, shared backups or other users' data. Treat writable files as untrusted, never execute them as root or automatically install them. Use a dedicated quota-limited filesystem/directory and separately approved deployment/readback via existing operator/effect lane. A live SQLite database needs its own application-coordinated backup/transaction policy; use a consistent copy first. No internet crawling from this sandbox. Network-enabled services remain separately reviewed, credential-isolated and restricted to their approved destination.
